能力速览

Claude Code是Anthropic面向软件开发的Agent产品，可以读取代码库，理解错误和需求，修改文件、运行命令与测试，并交付代码差异和说明。用户可从终端、编辑器、桌面或网页安排任务。值得关注的是按任务调用专门Agent，以及把复杂分工写成可检查、可重复运行的编排脚本；云端还能承接持续开发任务。它不等于Claude聊天应用，也不保证改动正确。模型、订阅和入口决定可用功能，远程指挥仍依赖本机在线；原生Windows的命令沙箱、云端配置继承及组织级评审都有明确限制。CC01、CC02、CC07、CC08、CC11、CC12、CC18

协调多条项目任务 Code Projects中的目标、仓库、指令与共享资料 协调对话分派云端开发线程，各自形成分支和拉取请求；部分工作可通过Remote转本地 Code Projects仍为公开beta，向Pro／Max／Ultra逐步开放，当前不面向Team／Enterprise；不能据名称推定等同A类Claude Projects；F/O CC13
检查代码变更并跟进PR问题 本地差异或GitHub PR、规则、CI失败与反馈 会话可讨论、修改代码；组织Code Review提交行级发现；Cloud Auto-fix在条件满足时修复并推送更新 三个入口分开：Code Review服务只读且不构建／运行代码；Auto-fix需GitHub App等条件。不能把服务评审写成已执行测试或自动合并；F/O CC11、CC14

官方案例A：保留行为的旧代码重构。 官方教程输入为现有utils.js、使用ES2024能力的要求及“保持原行为”约束，预期输出是实际代码修改，再运行项目测试检查。它展示代码阅读、修改和验证的连续任务，不是已证明行为完全等价的项目记录。O/J CC03

官方案例B：跨版本技术问题的交叉研究。 动态编排文档以“Node.js权限模型从v20到v22发生什么变化”为输入，组织多角度检索和核查，输出带引用的报告；无法核实的说法单列。此例展示Claude Code从代码任务向研究辅助扩展的产品入口，不能把多个Agent相互核查当成独立第三方验证。O/J CC08

官方案例C：PR提交后的持续修复。 Cloud文档展示Auto-fix监测GitHub PR的CI失败及评审反馈，读取失败线索，在认为问题明确时修改并推送代码，输出后续提交而非仅一段建议。它依赖仓库连接、权限及可用云环境；不意味着每条意见都能自动处理，更不等于已获准合并。O/J CC11

以上均为官方教程／功能示例。本轮没有运行案例，也未取得足以支持其成功率或优于Codex的独立验证。

3. 突出优势与差异化能力

  1. 专门角色与可重复编排是可辨认的组织方式。 子Agent可按任务匹配被调用；动态编排进一步把分支、循环和中间结果放到脚本及运行时中，主会话不必逐步保存所有细节。这是公开产品形态差异，不证明多Agent一定更准或Codex无法借助工具实现类似任务。F/J CC07、CC08
  2. 代码会话可连接更长的开发任务过程。 独立工作副本、云会话、远程指挥、PR Auto-fix和Code Projects分别覆盖并行修改、持续执行和项目协调。辨识点在这些入口如何组织任务；Codex同样具有本地／云端与并行能力，不能用“一个只有终端、一个有平台”概括。F/J CC10、CC11、CC12、CC13
  3. 评审按任务入口与执行环境分层。 会话评审、云沙箱Ultrareview与组织Code Review是不同形态，后者还与Cloud Auto-fix分开。评审的粒度、谁发起、能访问什么、是否能运行代码及如何留下反馈，需要逐入口理解；不能将“官方称核查发现”写成统一已验证的准确率。F/J CC14、CC20、CC11

扩展是两者共同能力：项目指令提供背景，Skills提供任务知识，MCP连接系统，Hooks在指定节点执行动作，插件组合扩展。Codex也有Skills、MCP、Hooks及子Agent，不把这些列为Claude Code独占优势。F/J CC06、[CX11]、[CX12]

4. 能力边界与使用限制

类型 可确认情况及影响 证据
正确性与验证 会修改文件、能运行测试与任务正确是不同结论；未覆盖路径、外部系统和复杂迁移仍可能出错。官方教程并非同条件效果测试 J；依据CC02、CC03
权限与项目指令 权限规则由客户端执行；CLAUDE.md中的行为要求不是访问控制。自动处理部分权限请求不等于无限访问，配置与插件需要分别受约束 F CC17
命令隔离／Windows 内置命令沙箱当前支持macOS、Linux、WSL2；原生Windows命令不在该内置沙箱中执行。沙箱仅约束其覆盖的命令，文件工具、MCP、Hooks不因此统一被隔离；这不表示Claude Code不能在Windows运行 F CC18
本地、Remote与Cloud 本地会话和Remote依赖执行电脑；Cloud可在本机关闭后继续，但有网络、凭据及资源条件。云会话等待授权、登录等也可能空闲到期；恢复会话不保证恢复当时所有后台任务 F CC11、CC12
云端配置和仓库 本机配置、工具与凭据不会自动完整迁移；Code Projects云线程会读仓库CLAUDE.md，但不自动带入仓库Skills、.mcp.json和本机设置。当前托管克隆及PR创建围绕GitHub；其他仓库可用本地打包方式，但该路径不能直接向原GitLab／Bitbucket远端推送 F CC11、CC13
模型与渠道 直连、Apps Gateway与第三方云别名映射可能不同，Fable 5.2不是所有用户默认模型。CLI可使用第三方渠道，不代表同一凭据可开启Cloud或Remote；Remote不支持API密钥等若干接入方式 F CC04、CC12
各功能并非同等开放 动态编排、Code Projects、Cloud和组织Code Review的计划及管理条件不同；Code Projects beta不能写成企业全面开放。当前功能存在不代表实际账号已取得权限 F CC08、CC11、CC13、CC14
评审服务的边界 组织Code Review面向Team／Enterprise及GitHub，由组织启用，单独计用量；只读、不构建或运行代码，不批准或阻止合并。无发现不代表无错误。会话内评审及Cloud Auto-fix另看，不能套用同一行为描述 F/O CC14、CC15
深度评审和其他CI入口 Ultrareview为云沙箱研究预览，需显式发起，存在差异规模、账号及提供方限制；不能把上述静态服务边界套给它。Claude也可通过自有GitHub／GitLab CI运行评审，不能由组织服务以GitHub为主推断整个产品不能处理GitLab F/O CC20、CC14
区域支持 2026-11-12生效的官方支持地区政策覆盖Claude Code及指定云／转售渠道，中国大陆不在支持名单。能看到网页、下载客户端或采用云渠道不能直接证明被支持 F CC19
尚未开放／未核实 Code Projects对组织计划尚未开放；具体账户灰度、第三方模型实际映射、跨平台配置一致性、长任务完成质量及两产品修复率差异为U。没有依据说Claude Code不能处理非代码文件，也没有依据说其自动化任务已可稳定无人干预 F/U CC04、CC13

6. 典型应用与能力价值

J：Claude Code的代表应用包括理解陌生项目、修复可复现问题、修改跨文件功能、补充测试及审阅变更。复杂任务可用专门Agent、编排脚本和独立工作副本分担，再把结果交回主会话；云端和PR跟进入口使任务可超出一次聊天。对读者最有价值的认知是：开发Agent的能力既来自模型，也来自它能读到什么、在哪里执行、如何分工，以及交付哪些可检查记录。它与Codex值得同时研究，是为了认识这些组织与控制差异，不是已有证据证明谁更强。
